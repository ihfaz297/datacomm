The exam questions, in the order you'd do them

8 steps from table to trained network

Read the question in italics and answer it in your head (or on paper) before you open the answer. That's what makes it stick.

1

Encode the features

Models only take numbers. What do you do with Yes/No? With "Sometimes"? With the Animal column? With Class?

Show the answer
  • Yes/No columns (Give Birth, Can Fly, Have Legs): Yes = 1, No = 0.
  • Live in Water: No = 0, Sometimes = 0.5, Yes = 1. This is ordinal encoding, which is fine because the values have a natural order. The safe alternative is one-hot: three columns (water_no, water_sometimes, water_yes) with a single 1 in each row. That costs 2 extra inputs.
  • Animal: drop it. It's an identifier, not a pattern.
  • Class (target): Mammal = 1, Non-mammal = 0.
  • Scaling: every value here is already between 0 and 1, so there's nothing to do. Numeric columns (height in cm, weight in kg) get standardised, z = (x − mean) / std, so no column dominates just because its numbers are bigger. If a column is skewed, like view counts running from 50 to 50,000, take the log first.

Each row becomes an input vector. Frog is x = [0, 0, 0.5, 1] with y = 0.

Trap

Never encode an unordered category as 0, 1, 2. If colour is red = 0, green = 1, blue = 2, the model thinks blue is "more" than red. Use one-hot for anything without a real order.

Feature-engineering bonus

Replace Live in Water with two flags, "lives on land" and "lives in water". Frog then gets 1 for both, which describes it better than "0.5".

2

Draw the network

How many input nodes? How many output nodes? How many hidden layers, and how wide?

Show the answer
Rules of thumb
  • Input layer: one node per encoded feature, so 4 here (6 if you one-hot the water column).
  • Output layer: binary means 1 node, k classes means k nodes, regression means 1 node. [Ranjan]
  • Hidden layers: start with two. Use sizes from 4, 8, 16, 32…, with the first layer about half the number of inputs and each layer after that half the one before. [Ranjan]
  • Other common sizing rules: between the output and input sizes, about √(inputs), or about the mean of the input and output sizes. [general]

Apply them: half of 4 is 2, √4 is 2, and (4 + 1) / 2 is 2.5. Every rule says 2 hidden neurons.

Answer: 4 → 2 → 1. One hidden layer of 2 ReLU neurons, then 1 sigmoid output that gives P(mammal). With only 5 rows, start simple. If the question wants Ranjan's two hidden layers, the halving rule runs out of room at 4 inputs (it would give 2, then 1), so draw 4 → 2 → 2 → 1.

Label these on your drawing: the feature name on each input, "+1" bias nodes, the activation under each layer, the weight matrices W⁽¹⁾ (2×4) and W⁽²⁾ (1×2), and "ŷ = P(mammal)" at the output.

If the question says "simplest possible", this is the wrong drawing. Go to 2b.

2b

"Simplest possible" network: one neuron

F2021 Q3b(i) · F2013 Q4

Do you need a hidden layer at all? Look at the Give Birth column again.

Show the answer

No hidden layer. One neuron is enough because the classes are linearly separable: Give Birth alone splits them, so a single straight boundary (a flat plane in 4-D) does the job. Hidden layers are only needed when no straight boundary exists, as with XOR.

z = w₁x₁ + w₂x₂ + w₃x₃ + w₄x₄ + b
ŷ = 1 (mammal) if z ≥ 0, else 0 (step, threshold 0)

  • Learnable parameters: 4 weights + 1 bias = 5.
  • Bias ≈ −1: draw the bias as an extra input fixed at +1 with weight b = −1. Some books draw an input fixed at −1 with weight θ = 1 instead, which is the same thing. Either way, the weighted inputs must add up to at least 1 before the neuron fires.
  • How a set of feature values is fed in: one animal per forward pass. Its 4 encoded values go to the 4 input nodes together as the vector x = [x₁, x₂, x₃, x₄], along with the constant bias input. In training, rows are fed one after another (perceptron rule) or in batches (gradient descent).
  • Activation: a step at threshold 0, as the question asks. Use sigmoid instead if you want a probability and gradient-descent training.
  • Data for this network: 5 / 0.1 = 50 rows (see step 6).

Weights that work with b = −1: w = [2, 0, 0, 0], so z = 2·birth − 1.

AnimalbirthzŷTruth
Human1+11Mammal ✓
Python0−10Non-mammal ✓
Whale1+11Mammal ✓
Frog0−10Non-mammal ✓
Bat1+11Mammal ✓

Training it: start from small random weights and apply the perceptron rule, w := w + η(y − ŷ)x and b := b + η(y − ŷ). It only changes the weights on mistakes, and it's guaranteed to converge here because the data is linearly separable.

"Suitable" vs "simplest possible": for "suitable", draw 4 → 2 → 1 (step 2). For "simplest possible", draw this single neuron and give the reason it's enough: the data is linearly separable.

3

Choose activation and loss functions

What goes in the hidden layer, what goes at the output, and which loss matches that output?

Show the answer
  • Hidden layer: ReLU, max(0, z). It's cheap to compute and doesn't flatten out for z > 0, so gradients don't vanish. [Ranjan]
  • Output: sigmoid, 1/(1 + e⁻ᶻ). It gives P(mammal) between 0 and 1. Predict Mammal if it's 0.5 or more. [Ranjan]
  • Loss: binary cross-entropy (log loss). It's the matched pair for sigmoid, and the gradient comes out as (ŷ − y)·x.
  • Optimizer: Adam or RMSprop at the default learning rate, or plain gradient descent with η around 0.01 to 0.1.
  • Metric: accuracy, since the classes are near balanced. For imbalanced data use precision, recall and F1.
If the task were…Output layerLoss
Mammal or not (this)1 neuron, sigmoidbinary cross-entropy
Mammal / Bird / Reptile / Fish / Amphibian5 neurons, softmaxcategorical cross-entropy
Lifespan in years1 neuron, linearMSE
Trap

Softmax on 1 output neuron always outputs 1, so the model can't learn. Sigmoid with MSE learns very slowly when it's confidently wrong, because of the extra σ′ ≤ 0.25 factor in the gradient.

5

Initialise the weights

Why not just start every weight at 0? And why small numbers rather than big ones?

Show the answer

Answer: start the weights at small random values and the biases at 0.

  • Why random: if every weight starts equal, both hidden neurons compute the same number, get the same gradient, and stay identical forever. Your 2 neurons act like 1. Random starting values break this symmetry, so each neuron can learn a different pattern.
  • Why small: big weights push the sigmoid into its flat ends, where the gradient is about 0, and learning stalls.
  • How small depends on the layer (this is what Keras does):
    • He, for ReLU layers: W ~ N(0, 2 / fan_in). For the hidden layer, fan_in = 4, so σ = √(2/4) ≈ 0.71.
    • Glorot / Xavier, for sigmoid or tanh (and Keras's default): W ~ U(−L, L) with L = √(6 / (fan_in + fan_out)). For the output layer, L = √(6/3) ≈ 1.41.

An example random start (one possible draw):

W⁽¹⁾ = [[0.42, −0.31, 0.85, −0.12], [−0.66, 0.27, −0.09, 0.53]], b⁽¹⁾ = [0, 0]
W⁽²⁾ = [[0.91, −0.48]], b⁽²⁾ = 0

What the untrained network says about Human, x = [1, 0, 0, 1]:

  • Hidden 1: z = 0.42 − 0.12 = 0.30, and ReLU gives 0.30.
  • Hidden 2: z = −0.66 + 0.53 = −0.13, and ReLU gives 0. This neuron is switched off for Human.
  • Output: z = 0.91 × 0.30 − 0.48 × 0 = 0.273, so ŷ = σ(0.273) ≈ 0.57.

A freshly initialised network is close to a coin flip. Training is what moves these weights until Human gets close to 1 and Python close to 0.

Trap

"Initialise all weights to zero" loses the mark. Zero is only fine for the biases.

6

Estimate the data you need

You have 5 rows and 13 parameters. Is that enough? What would be?

Show the answer
Rule · Baum–Haussler, quoted in Haykin

N ≈ W / ε

N is the number of training examples, W is the number of free parameters (weights and biases), and ε is the fraction of errors you'll accept on new data. For about 10% error, ε = 0.1, so N ≈ 10 × W. That's where "10 examples per parameter" comes from. [Haykin]

  • Training rows: 13 / 0.1 = 130 for 4 → 2 → 1. The one-neuron network in 2b needs 5 / 0.1 = 50.
  • Hold-out data: you also need rows the model never trains on. With a 70 / 15 / 15 train / validation / test split, 130 training rows means about 190 rows in total.
  • Coverage: every class, and every value of every feature, should show up several times. Right now only Frog has "Sometimes", and only Bat can fly.

Verdict: 5 rows is about 26 times too few. With 13 knobs and only 5 rows to satisfy, the network can fit the data in endless different ways, and none of them is guaranteed to work on a new animal.

7

Estimate the training duration

If you have 130 rows, batch size 16 and 100 epochs, how many weight updates is that? Roughly how long would it take?

Show the answer

updates = epochs × ⌈N / batch size⌉
time ≈ updates × time per update

  • Batch size: pick a power of 2. Start with 16, or 128 if the classes are imbalanced. [Ranjan]
  • Epochs: start with a few dozen and watch the validation loss. Stop when it stops improving (early stopping), and allow up to about 100. [general]
  • With 130 rows: ⌈130 / 16⌉ = 9 updates per epoch, so 9 × 100 = 900 updates. Each update on a 13-parameter network takes microseconds, so the whole run takes well under a second on a laptop.
  • With the real 5 rows: the batch of 16 is bigger than the dataset, so there's 1 update per epoch (full-batch gradient descent), and 100 epochs is 100 updates.
Trap

Epochs are passes over the whole dataset, not batches. epochs=4, batch_size=512 says nothing about the dataset size until you know N.

8

Guard against overfitting

13 knobs and 5 rows. What will the network do, and what are your defences?

Show the answer

What happens: the network can score 100% on the 5 rows by memorising them, and that score means nothing. You spot overfitting when the training loss keeps falling while the validation loss rises. If both stay high, that's underfitting: the model is too simple or hasn't trained enough.

Defences, strongest first:

  1. More data. This is the real fix (step 6).
  2. Hold out data. Use a train / validation / test split. With tiny data, use k-fold cross-validation, or leave-one-out: with 5 rows, train on 4 and test on 1, five times.
  3. Early stopping: stop training when the validation loss starts to rise.
  4. Smaller model: fewer neurons leave less room to memorise. Try 4 → 2 → 1, or even logistic regression (5 parameters).
  5. Regularisation: an L2 penalty keeps the weights small. Dropout randomly switches off neurons during training. Ranjan's default is 0.5 after every hidden layer, never on the input, and above 0.5 hurts. [Ranjan] With only 2 hidden neurons, dropout 0.5 kills half the layer, so L2 is the gentler choice here.
  6. Drop the ID column. A unique name per row is a memorisation shortcut.

Show the answer

Encode first:

  • Target: 3 classes, one-hot as [1,0,0], [0,1,0] and [0,0,1].

(a) Network: 7 → 4 → 3. 7 inputs (4 numbers + 3 colour flags), one hidden layer of 4 ReLU neurons (about half of 7, rounded to a power of 2), and 3 softmax outputs, one per size.

(d) Number of iterations: don't fix it in advance. Hold out a validation set, train one epoch at a time, and track both the training and the validation loss. Stop when the validation loss hasn't improved for about 10 epochs (early stopping) and keep the best weights. For a rough number: 470 rows at batch size 32 is ⌈470 / 32⌉ = 15 updates per epoch, so 100 epochs is 1,500 updates.

The deeper lesson

Why not just use a decision tree?

One question, "Gives birth?", classifies all 5 rows correctly. Logistic regression (a single neuron, 5 parameters) fits them too. The exam uses a neural network on this table because the table is small enough to draw by hand, not because a network is the right tool for it.

The real lesson comes from two animals the table doesn't include:

AnimalbirthflywaterlegsTruth"Gives birth" rule says
Platypus (lays eggs)000.51MammalNon-mammal. Wrong.
Frog000.51Non-mammalNon-mammal
Boa constrictor (live young)1000Non-mammalMammal. Wrong.

Platypus and Frog have exactly the same four numbers but different answers. No model, however big, can separate two rows that look identical. Only a new feature can. Add "produces milk", which is literally what makes an animal a mammal, and the problem disappears.

That's the whole of feature engineering vs model selection: when the inputs can't tell two cases apart, a better model can't either. Fix the data first. Pick a bigger model only when the features are already good and you have the rows to feed it.

Doomsday · any table, 9 lines

The answer template

  1. Encode: yes/no to 0/1. Ordered values to ranks (0, 0.5, 1). Unordered categories to one-hot. Numbers get standardised (log first if skewed). Drop ID columns. Target to 0/1 (or one-hot for k classes).
  2. Draw: inputs = number of encoded features. Hidden ReLU layer(s) of about half the inputs (a power of 2). Output is 1 sigmoid / k softmax / 1 linear. Label the biases. For "simplest possible" with linearly separable classes, use no hidden layer: one neuron per output.
  3. Activation and loss: sigmoid + binary cross-entropy, softmax + categorical cross-entropy, linear + MSE. Adam or RMSprop.
  4. Count: sum of (inputs + 1) × neurons over the layers.
  5. Initialise: small random values (He for ReLU, Glorot for sigmoid), biases 0. Never all zeros, because of symmetry.
  6. Data: N ≈ W / ε (Baum–Haussler), so about 10 × parameters for 10% error, plus validation and test rows.
  7. Duration: updates = epochs × ⌈N / batch⌉. Batch 16 to 128. Train until the validation loss stops improving.
  8. Overfitting: more data, a validation split with early stopping, a smaller network, L2, dropout 0.5, cross-validation.
  9. Optimise training: standardise inputs, mini-batches, Adam or RMSprop with a tuned learning rate, He / Glorot start, early stopping, class weights if imbalanced, batch normalisation if deep.

For the animal table: 4 → 2 → 1, ReLU then sigmoid, binary cross-entropy, 13 parameters, He / Glorot start, about 130 training rows (about 190 in total), 9 updates per epoch at batch 16, and leave-one-out with L2 because 5 rows can't support a held-out test set. Simplest possible: one neuron, 5 parameters, step at threshold 0.
